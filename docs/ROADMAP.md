# Roadmap

This roadmap records intended work. Items are not promises of delivery dates or claims of completed features.

## Current foundation

- Six measurement dimensions with sandbox and reference-dictionary activities.
- An optional AI-assisted creative workflow and a shared provider client.
- English project documentation and an English main entry page.
- A local development workflow and production-bundle checks.

Many activity labels, reference entries, and prompts remain Chinese. AI features depend on a configured backend. Full offline operation and universal provider compatibility are not established.

## Priorities

| Priority | Work | Evidence of completion |
| --- | --- | --- |
| Localization | Move activity text, errors, and prompts into a consistent translation structure. | An English user can complete each documented activity without untranslated instructions. |
| Measurement quality | Review reference values and conversion boundaries; record sources and approximations. | Reviewed examples and focused checks for unit factors and edge cases. |
| Reproducibility | Resolve inherited lint findings and make validation results easier to reproduce. | Documented commands with accurate pass/fail results on a fresh checkout. |
| Accessibility | Review keyboard interaction, focus, contrast, motion, and labels. | Recorded checks and fixes for the supported activity flows. |
| Assets and offline use | Inventory network dependencies and localize assets where licensing permits. | An explicit list of remaining requests and a repeatable offline check. |
| Provider behavior | Improve configuration validation and failure presentation. | Clear errors and reviewed behavior for the providers actually tested. |
| Learning materials | Add short activities and teacher-facing explanations grounded in the implementation. | Reproducible exercises with a clear physical or reference check. |

Hosted services, accounts, analytics, and institutional classroom management are outside the current project scope. Contributions should strengthen the local learning experience before adding operational complexity.

## Proposing work

Open an issue describing the learning or developer need, the smallest useful change, and a way to verify the result. Claims of educational effectiveness or broad adoption need evidence; they are not roadmap acceptance criteria by themselves.
